# 干活指南（给驱动这个工具的 Agent / 人）

README 讲的是**工具本身**。这份讲的是**你在三个关卡上具体该怎么干**，
以及已经踩过的坑——那些坑不写下来，下一轮一定会重踩。

## 先把分工记住

| 谁 | 干什么 |
| --- | --- |
| PaddleOCR | 解析 PDF：OCR、版面、阅读顺序（不输出逐段置信度） |
| 脚本 | 搬运、渲染页面图、打包、校验、出报告 |
| **你** | **判断与转写**：对着页面图校准低分段；把内容写成 EPUB |

脚本停下来的三个地方，都是它在说"这里需要判断，我判断不了"。

---

## 循环

```bash
pdf2epub run                              # 跑到需要你的地方，退出码 3
pdf2epub show calibrate|compose|check     # 直接看工单，不用翻路径
#  …… 干活 ……
pdf2epub run                              # 继续；已完成的阶段不会重来
```

退出码：`0` 成功 / `1` 失败 / `2` 跑完了但有告警 / `3` **轮到你了**。

阶段重跑会自动把后面的阶段重置回 pending，所以不用担心旧状态残留。
反复跑同一个命令是安全的。

## 大书：解析每 20 页一片，干活也要分批

### 解析怎么切：每片 20 页，接缝必须核（硬要求）

**解析一律按 20 页一片**（`pdf2epub.toml` 的 `max_pages_per_task = 20`）。不是
"超限才切"，也不是切得大一点省事：

- 一个分片一个解析 job，小片并行，整本书更快出结果——200 页一片等于把整本书
  排成两个慢任务。
- 片与片之间的**接缝**（前一片最后一页 + 后一片第一页）是整本书里唯一跨边界的地方，
  页码偏移算错、某片少解析一页都只会在这里露出来。片小，缝才核得过来。

prepare 会自动做**交界处校验**，结论写在 `<run>/parsing/boundary.md`：

1. 分片计划本身首尾相接、不重不漏；
2. 每片产物里的页数 == 计划页数（同时比对后端自报的提取页数）；
3. 每道缝的两页在产物里是否有正文（0 字 = 可疑，必须看图）。

**接缝两页是校准阶段的必做项**：校准工单有「交界处核对」一节，把那两页的页面图列好
了。对着图看"接缝上下一句能不能接上"——不能断在半句，也不能重复一整段；结果写进
`calibrate/notes.md`。校验发现问题时 prepare 会发 `BOUNDARY_CHECK` 告警，别当噪声忽略。

### 你的活也要分批，不要一次性喂进去

**你的活不能按整本书一次性做**。300+ 页的书，`calibrate/source.md` 有几十万字：
一次性读完再写成 EPUB，上下文塞不下，也没法逐段复核。规矩是**按页数或章节分批，
一批做完再做下一批**：

| 阶段 | 分批粒度 | 具体做法 |
| --- | --- | --- |
| 解析 | 20 页一片（脚本自动） | 不用你管；但接缝两页要核（见上） |
| 校准 | 50～100 页，或一章 | 只核对这一段的低分段（`segments.json` 里按页码筛），改完 `source.md` 再跑下一批 |
| 撰写 | 一章一个 xhtml | 写完一章就 `pdf2epub run` 打包校验一次，过了再写下一章；不要在一条回复里输出整本书 |

分批**不是**把书拆成几个 run，而是在同一份工作稿 / 同一个 `build/` 上分次动手：
`source.md` 和 `build/OEBPS/text/` 都是累加的，中途 `pdf2epub run` 不会丢掉已有内容
（注意 `scripts/compose_mathml.py` 会清空 `text/` 重写，要分批手写就别用它）。

### 先看清章节边界：`scripts/split_pdf.py`

不知道在哪切、一章几页，先 `--list`：

```bash
python scripts/split_pdf.py "book.pdf" --list
```

它会打出页数、书签目录，以及流水线会自动切成几份。要真落成分文件就用：

```bash
# 按一级书签切，每份不超过 80 页（只在章节之间切，不会切在章中间）
python scripts/split_pdf.py "book.pdf" --by-chapters --max-pages 80 -o chunks/

# 没有书签、或者书签不可信：纯按页数切
python scripts/split_pdf.py "book.pdf" --by-pages 80 -o chunks/

# 自己指定页段（1 基闭区间）
python scripts/split_pdf.py "book.pdf" --ranges 1-40,41-120 -o chunks/
```

产出 `chunks/<stem>.p0001-0080.pdf` 和一份 `chunks/split-manifest.json`（每份的起止
页码、页数、对应章标题，可直接用来规划分批）。加 `--dry-run` 只出计划、不写文件。

**别把切出来的分片再喂给 `pdf2epub init`**——那会变成几个互不相干的 run，最后合不成
一本书。唯一合理的例外：某一章解析得特别差，想单独拿它试一次后端。

## 关卡一：校准（calibrate）

### 会给你什么

```
<run>/calibrate/
├── report.md       ← 工单：低分段清单 + 原文 + 上下文 + 对应页面图路径
├── segments.json   ← 同一份清单，机器可读
├── source.md       ← ★ 你直接编辑这个
├── pages/          ← 页面截图（page-0007.png = 第 7 页）
└── images/         ← 解析抽出的图
```

### 怎么干

1. **先做「交界处核对」**（`report.md` 里第一节）：每道缝的两页对着页面图看一遍，
   接缝上下要能接上。分片边界是最容易丢内容又最容易被忽略的地方，先确认它没坏，
   后面的校准才有意义。
2. **再看 `report.md` 的低分段清单**，它按分数升序排列。
3. **逐页打开 `pages/*.png`**，把图上内容和工作稿里的对应段落比。
4. 只改**确认是识别错误**的地方，改在 `source.md` 里。
5. 改完 `pdf2epub run`。确认不用改就 `pdf2epub done calibrate --note "…"`。

书厚就按页段分批，一次只核对一段（见上面的「大书」）：低分段一多，整本啃完
既慢又容易看走眼。

### 别一页页硬啃，先按模式找

实测一篇 18 页的 LaTeX 论文有 55 段低分内容，逐段核对很慢。真正有效的是
**先按已知的错误模式全局搜一遍，再对可疑处看图确认**。上一轮用到的模式：

| 想找什么 | 搜什么 |
| --- | --- |
| 公式右边被吞了符号 | `$= `（美元号后直接等号）；`= \operatorname{diag}` 前面没有变量 |
| `Λ` 被吞或被认成别的字 | `\\mathbf { \\Psi }`、`\\mathbf { \\omega }`、`对角矩阵 \$= ` |
| 下标被吞成纯文本 | 中文紧挨着一个孤立字母，如 `∪ M 的特征值集合`（应是 `M₋`） |
| 字符被当成排版符号 | `\\underline { { \\mathbb { E } } }`（应是"正"）、`\\textsf { F }`（应是"下"） |
| 中文引号被输出成 `” ` | `” `（右引号夹空格） |
| 被认成一串上标 | `<sup>作用于</sup> <sup>A</sup>` |
| 残余杂质 | 中文里多出的 `o`（应是句号）、` e e`、多余右括号 |
| 空基导致的怪结构 | `& ^`、`& _`（数组单元格里只有上标、没有底） |

**改之前必须看图。** 这些模式只负责"值得看一眼"，不负责"确认是错的"。
上一轮有一处 `m₁` 我按上下文推断应为 `m_i`（同页另两处都是 `m_i`，且指数必须
跟着下标走），这是少数靠推理定的，也记在了 `notes.md` 里。

### 规矩

- 只改识别错的地方。不要重写文案、不要调风格、不要补原文没有的内容。
- 图上确认机器没认错的，保持原样。
- **认不出来的宁可不改**——改错比不改更糟。把情况写进 `calibrate/notes.md`。
- 改动记一份 `notes.md`，说明改了什么、依据是什么。下一轮或用户会看。

## 关卡二：撰写（compose）

### 会给你什么

```
<run>/build/
├── BRIEF.md          ← 撰写说明
├── book.json         ← 书目 + 阅读顺序（模板已放好）
└── OEBPS/
    ├── text/         ← ★ 你写章节
    ├── images/       ← 脚本搬好的图
    └── style/base.css
```

### 用现成的脚本

```bash
python scripts/compose_mathml.py --run <run 目录> \
    --title "书名" --author "作者"
```

它把机械的部分做掉：标题分级、段落/列表、`$$…$$` 与 `$…$` 转 MathML、
公式编号右对齐、转义、`book.json`。**需要 `pip install latex2mathml`。**

**书厚的不用死等它**：它会清空 `text/` 一次性重写，几百页的书按章分批手写更稳
（见上面的「大书」）。

它是示例脚本，不是流水线的一步——章节怎么切、标题叫什么，仍然由你定，
也应该由你复核。脚本跑完**务必检查**：

- 切出来的章数对不对（标题层级启发式是按 MinerU 产物调的；PaddleOCR 的
  markdown 层级可能不同，用 `scripts/compose_mathml.py` 前先复核）
- 标题有没有被截断或粘连
- 目录章（印刷目录）的页码是否还对着原书

### 章节 XHTML 的硬要求

只有三条：良构 XML、根元素带 XHTML 命名空间、有 `<head><title>` 和 `<body>`。
`content.opf` / `nav.xhtml` / `META-INF/container.xml` **不用你管**，打包时生成。

**公式必须是合法 MathML。** 仅仅"XML 良构"不够——`<msup>` 这类元素只允许
固定个数的子元素，塞多了 XML 照样能解析，但 EPUBCheck 会判 RSC-005。
`scripts/compose_mathml.py` 里的 `bad_structure()` 就是拦这个的。

## 关卡三：格式（check）

脚本跑自检 + EPUBCheck，把结果写成 `check/report.md`，精确到文件、行号、原文片段。
**这里只有报告，没有修复器**——改是"你"的事，脚本负责把问题定位得足够准。

### 常见问题归谁

| 码 | 含义 | 谁该处理 |
| --- | --- | --- |
| `OPF-014` | 用了 MathML 但 manifest 没声明 | **脚本**（`epubpack` 已自动探测） |
| `RSC-005` | XHTML 解析失败 **或** MathML 结构违规 | 你（改 `build/` 下的文件） |
| `RSC-006` | 引用了远程资源 | 你（EPUB 不允许远程资源） |
| `RSC-007` | 引用的资源不存在 | 你（可能真丢了图，要看上下文决定补图还是改写正文） |
| `OPF-085` | `identifier` 标了 `urn:uuid:` 但不是合法 UUID | **脚本**（已自动纠正） |
| `OPF-003` | manifest 与目录树不一致 | **脚本**（打包时按目录树重建） |

判断标准：**包内文件层面的问题（OPF/nav/container/zip）是脚本的活，正文层面的
问题（内容、引用、MathML）是 LLM 的活。** 如果发现某个包内问题反复出现，
那是脚本的 bug，应该去 `src/pdf2epub/` 修，而不是每次手工绕过去。

### 实在改不动的

`pdf2epub done --accept --note "原因"` 收尾。产物保留，同时留下明确告警，
**不会静默当成功**。不要为了让它"通过"而把内容删掉或注释掉。

## 已经踩过的坑

跑第一份真实 PDF 时暴露出来的。前三个已经在代码里修好了，但知道原因能省下
下次的排查时间；后两个是使用方法上的教训。

### 1. MinerU 时代的 bbox 有**三套坐标系**（已修；换 PaddleOCR 后无此问题）

| 来源 | 坐标系 |
| --- | --- |
| `model.json`（vlm 模式，版面层） | 0-1 归一化 |
| `content_list.json`（正文层） | **0-1000 整数归一化** |
| 真像素 | 需要页面尺寸才能换算 |

原来的实现只把一边归一化，两套坐标比不出 IoU，**55 段低分段全被贴上第 1 页**。
页码错得静默无声——报告看着正常，只是页数不对。

实测同一份产物里，`content_list` 的 `[292,135,702,185]` ÷ 1000 正好等于
`model.json` 的 `[0.294,0.136,0.703,0.186]`。

判定必须**整份文档统一做**，不能一页一页判：某页恰好只放了一小块内容时，
按页判断会把这一页误判成 0-1 坐标，于是只有这一页配不上分数，更难发现。

### 2. 版面层是**逐行**、正文是**整段**（已修）

带分数的是 `ocr_text`——逐行的 OCR 结果；`content_list` 的条目是整段。
只比 IoU 的话，逐行框和整段框重叠率很低，**正文和公式会整片配不上分数**，
而那恰恰是最需要复核的部分。改成"至少一半重叠"后，配上分数的段落
从 185/290 涨到 246/290。

一段命中多行时取**最低**分：整段里只要有一处没把握，这段就值得看一眼。

### 3. `\binom{a}{b}^\top` 会产生**非法** MathML（已在示例脚本里兜住）

latex2mathml 会把上标挂到残缺的基上，产出 `<msup>` 里塞四个子元素的结构。
XML 良构、能解析、能打包，**只有跑真校验才会暴露**。

记在 `scripts/compose_mathml.py` 的 `sanitize()` 里。以后遇到"生成的 XML 看着没
问题但 EPUBCheck 报 RSC-005"，先怀疑这类**结构合法性**问题，而不是语法问题。

### 4. 提交信息别写长

用户明确说过："没人看"。一行标题就够。

### 5. 跑测试不该产生批量删除（`tests/conftest.py` 已覆盖 `tmp_path`）

pytest 默认只保留最近 3 次会话的 `pytest-N` 临时目录，**每次跑测试都会把更早那一份
整棵删掉**——一次几百个文件（实测每份约 300 个文件，连 `pytest-current` 符号链接算
600 多个）。沙箱化的 IDE 会把这种批量删除当成破坏性操作拦下来，agent 就没法一直
自动跑下去了。

所以 `tests/conftest.py` 覆盖了内置的 `tmp_path`：每个测试一个独享目录，但永不自动
删除。跑测试不再产生任何删除，代价是临时目录要手动清。

## 校准实测：PaddleOCR-VL 的高频问题（386 页技术书全量校准后总结）

来源：《超标量处理器设计》386 页全量校准（32 张表、19 道接缝、通读）。频率按
本次实测计，换书时分布会变，但"怎么发现"的模式可直接复用。

| # | 问题 | 频率 | 怎么发现 | 怎么处理 |
| --- | --- | --- | --- | --- |
| 1 | **跨页表格被拆成两张独立表**（续页重复表头，约半数带"续表"标记） | 5/32 张表 | 全文搜"续表"；或对每个表核对"行数 vs 原图" | `_work.py merge` 类脚本：续表数据行并入主表、删重复表头和"续表"标记；组标签 rowspan 要相应加大 |
| 2 | **组标签 rowspan 丢失 → 整行左移错位**（如 CRn/Op1 纵向合并贯穿全表时，只给了首行） | 1/32（表3.5） | 各行 `<td>` 个数不一致；渲染后列对不齐 | 按原图重建整表；group 列补 rowspan |
| 3 | **位段图/图内嵌内容被拆成表格行**（"31…0 / 未使用｜Way｜Set"变成一行 4 列） | 1/32 | 表格里出现与列语义无关的行 | 并回解释单元格，用 `<br/>` 保排版 |
| 4 | **O/0 字形混淆**（COP0→"COPO"、MFC0→"MFCO"） | 3 处 | 术语表/指令名核对；MIPS 语境必是 0 | 按标准记法改 |
| 5 | **HTML 转义把 `&` 放大成 `&&`**（AND/ANDI 的位与写成逻辑与） | 2 处 | 全文搜 `&amp;&amp;` | 改回单 `&amp;` |
| 6 | **行内公式字符丢失**（`16'h0000` 丢一个 0） | 1 处 | 公式逐条对照原图 | 直接改 |
| 7 | **条件符号 `!` 丢失**（BGTZ/BGEZ 的 `!Rs[31]`） | 3 处 | 指令语义核对（BLEZ/BGTZ 条件必然互补） | 补 `!` |
| 8 | **助记符与操作数丢空格**（`addi r7` → `addir7`） | 8 处 | 搜 `[a-z]{3,4}r\d` 这类粘连模式 | 补空格 |
| 9 | **跨页段落被切成两段**（按页拼接的必然结果）。不只片边界——**片内每次翻页都可能切断**（实测全书 42 个候选断点，34 处真断句） | 12/19 道接缝 + 34 处片内 | 规则化检测：左页末字符非终止标点（。！？：；…）且右页首字符是正文（非标题/图/表/列表/公式） | 合并：左尾右首都是 ASCII 字母时补空格，否则直接接；目录、图注后、指令清单要排除 |
| 10 | **表下脚注丢失**（表 11.2 的 `\* s-p/d-p` 说明） | 1 处 | 看原图表格下方有无小字 | 表后补一段 |
| 11 | 单元格内换行是**字面 `\n`** | 所有长文本表 | 搜 `\n` | 撰写阶段转 `<br/>`（属于 compose 的活，不要在校准里改） |
| 12 | **无逐段置信度** | 全书 | 低分清单恒为空 | 校准只能全量通读 + 表格对图 + 接缝核对；管线已在有接缝时强制停留校准 |
| 13 | **汇编寄存器 `$` 记法与行内公式 `$…$` 约定冲突**（`$k1`、`JR $31`） | 若干 | 段落内 `$` 个数为奇数或 ≥3 | 撰写阶段按上下文判断，寄存器 `$` 按普通文本转义，不要当公式转换 |
| 14 | **原书自带笔误不是 OCR 错误**（"Branch on Great Than Zero"、"AMD AHL470V/7"、"寄存器重名"） | 若干 | 对图核对——图上这么印的就保留 | 保持原样；"宁漏勿错" |
