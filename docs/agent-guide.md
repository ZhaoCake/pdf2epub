# 操作指南（面向驱动本工具的 Agent / 操作者）

README 介绍工具本身；本文说明三个关卡上的具体操作方式，以及实践中确认有效的
方法与已知的陷阱。

## 分工

| 执行者 | 职责 |
| --- | --- |
| PaddleOCR | 解析 PDF：OCR、版面分析、阅读顺序（不输出逐段置信度） |
| 脚本 | 搬运、渲染页面图、打包、校验、出报告 |
| **LLM** | **判断与转写**：对照页面图校准解析结果；把内容写成 EPUB |

流水线停下来的三个位置，都表示"此处需要内容判断"。

---

## 运行循环

```bash
pdf2epub run                              # 执行到需要 LLM 的环节，退出码 3
pdf2epub show calibrate|compose|check     # 直接打印工单，省去翻找路径
#  …… 按工单工作 ……
pdf2epub run                              # 继续；已完成的阶段不会重复执行
```

退出码：`0` 成功 / `1` 失败 / `2` 执行完毕但有告警 / `3` **等待 LLM 处理**。
阶段重跑会自动将后续阶段重置为 pending；重复执行同一命令是安全的。

## 长文档：分片与分批

### 解析按 20 页一片，接缝必须核对（硬要求）

**解析一律按 20 页一片**（`pdf2epub.toml` 的 `max_pages_per_task = 20`），
不是"超限才切"，也不是切得越大越省事：

- 每片一个解析任务，小片并行，整本书更快出结果——200 页一片相当于把整本书
  排成少数几个慢任务。
- 片与片之间的**接缝**（前一片最后一页 + 后一片第一页）是整本书唯一跨边界的
  位置；页码偏移算错、某片少解析一页，都只会在这里暴露。片小，接缝才核对得过来。

prepare 收尾会自动执行**交界处校验**，结论写入 `<run>/parsing/boundary.md`：

1. 分片计划首尾相接、不重不漏；
2. 每片产物的页数与计划页数一致（同时比对后端自报的提取页数）；
3. 每道缝两侧的页面是否解析出正文（0 字即可疑，必须看图）。

**接缝两页是校准阶段的必做项**：校准工单的「交界处核对」一节列出了对应的
页面图。对照图片确认接缝上下文能够衔接——不能断在半句，也不能重复一整段；
结论写入 `calibrate/notes.md`。校验发现问题时 prepare 会发出 `BOUNDARY_CHECK`
告警，不要当作噪声忽略。

### LLM 的工作同样要分批

数百页的书，`calibrate/source.md` 有数十万字：一次性读完再转写，上下文容纳
不下，也无法逐段复核。**按页段或章节分批，一批完成后再做下一批**：

| 阶段 | 分批粒度 | 做法 |
| --- | --- | --- |
| 解析 | 20 页一片（脚本自动） | 无需干预；接缝两页要核对（见上） |
| 校准 | 50～100 页，或一章 | 只核对这一段的低分段（`segments.json` 按页码筛选），改完再进入下一批 |
| 撰写 | 一章一个 xhtml | 写完一章即 `pdf2epub run` 打包校验一次，通过后再写下一章；不要在一条回复里输出整本书 |

分批**不是**把书拆成多个 run，而是在同一份工作稿、同一个 `build/` 上分次进行：
`source.md` 与 `build/OEBPS/text/` 都是累加的，中途 `pdf2epub run` 不会丢失
已有内容（注意 `scripts/compose_mathml.py` 会清空 `text/` 重写，分批手写时
不要使用）。

### 先摸清章节边界：`scripts/split_pdf.py`

不确定在哪里切章、一章有多少页时，先看切分计划：

```bash
python scripts/split_pdf.py "book.pdf" --list
```

它会输出页数、书签目录，以及流水线将自动切成的分片数。确需落成分文件时：

```bash
# 按一级书签切，每份不超过 80 页（只在章节之间切，不会切在章中间）
python scripts/split_pdf.py "book.pdf" --by-chapters --max-pages 80 -o chunks/

# 没有书签、或书签不可信：纯按页数切
python scripts/split_pdf.py "book.pdf" --by-pages 80 -o chunks/

# 自行指定页段（1 基闭区间）
python scripts/split_pdf.py "book.pdf" --ranges 1-40,41-120 -o chunks/
```

产出 `chunks/<stem>.p0001-0080.pdf` 与 `chunks/split-manifest.json`（每份的
起止页码、页数、对应章标题，可直接用于规划分批）。加 `--dry-run` 只出计划、
不写文件。

**切出来的分片不要再喂给 `pdf2epub init`**——那会生成几个互不相干的 run，
最终无法合成一本书。唯一合理的例外：某一章解析质量特别差，想单独重试后端。

## scripts/ 工具箱

`scripts/` 下的脚本**不属于流水线**，是把实践经验固化下来的独立工具，
`--help` 查看用法：

| 脚本 | 功能 | 使用时机 |
| --- | --- | --- |
| `split_pdf.py` | 按书签/页数/页段切 PDF，出切分计划与清单 | 校准前摸清章节边界；需要分批作业时 |
| `submit_jobs.py` | 分批提交解析任务：逐个落盘 job_id、被拒退避重试 | 大书 prepare 被限流/拒绝之后（见教训 8） |
| `fetch_jobs.py` | 按 `jobs.json` 接续取回已提交的解析任务 | 同上 |
| `qc_scan.py` | OCR 体检：页级索引 + 六类全局检测，出 `qc-report.md` | **校准第一步**，先运行再动手 |
| `table_tool.py` | 表格台账 / 结构体检 / 对图核对清单 / 裁图换图 | 校准的表格专项（见关卡一） |
| `toc_check.py` | 原书书签 vs 解析产物逐条核对，出 `toc-check.md` | 原书带书签时，校准前运行 |
| `compose_mathml.py` | `source.md` → 章节 XHTML（公式转 MathML） | 小书一键成稿（见关卡二） |
| `compose_book.py` | 按 `compose-plan.json` 切章组书 | 分章撰写（见关卡二） |

## 关卡一：校准（calibrate）

### 交付物

```
<run>/calibrate/
├── report.md       ← 工单：低分段清单 + 原文 + 上下文 + 对应页面图路径
├── segments.json   ← 同一份清单，机器可读
├── source.md       ← ★ 直接编辑这个
├── pages/          ← 页面截图（page-0007.png = 第 7 页）
└── images/         ← 解析抽出的图
```

### 操作步骤

1. **交界处核对**（`report.md` 第一节）：每道缝的两页对照页面图查看，
   接缝上下文必须衔接。分片边界是最容易丢内容又最容易被忽略的位置，
   先确认它没有问题，后续校准才有意义。
2. **运行体检脚本**：`python scripts/qc_scan.py --run <id> --render`，
   按报告（`calibrate/qc-report.md`）逐项看图确认。
3. **低分段清单**（如有）：按分数升序排列，逐条处理。
4. **逐页对照 `pages/*.png`**，把图上内容与工作稿中的对应段落比对。
5. 只修改**确认是识别错误**的地方，改动落在 `source.md`；完成后 `pdf2epub run`，
   或确认无需修改时 `pdf2epub done calibrate --note "…"`。

书厚时按页段分批，一次只核对一段（见「长文档」一节）。

### 模式优先于通读

PaddleOCR-VL 不输出逐段置信度，低分段清单通常为空；真正有效的工作方式是
**先按已知错误模式全局搜索，再对可疑处看图确认**。`qc_scan.py` 已固化大部分
检测器（重复段、页码混入、跨页断句、裸 LaTeX、幻觉关键词等）；下表是它未覆盖、
需要手工搜索的模式：

| 目标 | 搜索模式 |
| --- | --- |
| 公式右侧被吞符号 | `$= `（美元号后直接等号）；`= \operatorname{diag}` 前缺变量 |
| `Λ` 被吞或认错 | `\\mathbf { \\Psi }`、`\\mathbf { \\omega }`、`对角矩阵 \$= ` |
| 下标被吞成纯文本 | 中文紧邻孤立字母，如 `∪ M 的特征值集合`（应为 `M₋`） |
| 字符被当作排版符号 | `\\underline { { \\mathbb { E } } }`（应为"正"）、`\\textsf { F }`（应为"下"） |
| 中文引号输出异常 | `” `（右引号夹空格） |
| 正文被认成上标 | `<sup>作用于</sup> <sup>A</sup>` |
| 残余杂质 | 中文里多出的 `o`（应为句号）、` e e`、多余右括号 |
| 空基导致的怪结构 | `& ^`、`& _`（数组单元格里只有上标、没有底） |

**修改前必须看图。** 模式命中只说明"值得看一眼"，不构成"确认有错"。
少数改动依赖上下文推理（例如某处 `m₁` 按同页其余写法推断应为 `m_i`），
这类修改必须记录在 `notes.md` 中。

### 表格：先体检、再对图、读不动的换图

表格是扫描书最容易损坏的部分，且损坏方式隐蔽：数值大多正确，问题集中在
**结构**（整列丢失、表头错位、整表只剩空壳）与**助记符**（0↔O、1↔I、点号
丢失）。推荐流程：

1. `python scripts/table_tool.py --run <id> check` —— 结构体检：行内单元格数
   不一致（rowspan 丢失导致整行左移）、疑似跨页续表、超长单元格（图被读成了表）。
2. `python scripts/table_tool.py --run <id> pages` —— 含表页渲染成 2 倍图
   （`calibrate/table-pages/`），并生成对图核对清单 `table-manifest.md`。
   逐张对照时**按章拆分给只读子代理效率最高**：每章一个，回报"哪张表哪一格不对"。
3. `python scripts/table_tool.py --run <id> crop` —— 把读不动的表裁成图
   （`calibrate/images/table-pNNNN-oK.png` + 换图清单 `table-images.json`）。
   阈值只看**宽度**：列 ≥9，或列 ≥6 且行 ≥15，或格子 ≥150——宽表在 EPUB 中
   无法重排；"行多"只是纵向滚动，"字多"反而 HTML 更好（可搜索）。
   阈值挑不出但**结构已坏**的表，逐个对图确认后用 `--extra 页:序号` 追加。
4. 换图只替换表格本体，**表题保留为正文**（可搜索）；撰写阶段按
   `table-images.json` 将对应 `<table>` 替换为 `<img>`。

### 书签核对：章节标题是否解析完整

字数、接缝、重复都有脚本核对，但"章节标题是否被吞掉"没有自动保障——章首
大字页解析不稳定，标题缺失或被拆成两行都出现过。原书 PDF 带书签时先运行：

```bash
python scripts/toc_check.py --run <id>
```

每条书签对到预期页（±1 页）的解析文本，未命中的写入 `calibrate/toc-check.md`，
逐条对图：标题丢失的按目录补插，拆成两行的合并。

### 高频问题清单

PaddleOCR-VL 在整本书全量校准中的高频问题。频率为一次实测的统计，换书时
分布会变，但"发现方式"与"处理方式"可直接复用：

| # | 问题 | 频率 | 发现方式 | 处理 |
| --- | --- | --- | --- | --- |
| 1 | **跨页表格被拆成两张独立表**（续页重复表头，约半数带"续表"标记） | 常见 | 全文搜"续表"；或对每个表核对"行数 vs 原图" | 续表数据行并入主表，删除重复表头与"续表"标记；组标签 rowspan 相应加大 |
| 2 | **组标签 rowspan 丢失 → 整行左移错位**（纵向合并贯穿全表时只给出首行） | 偶见 | 各行 `<td>` 个数不一致；渲染后列对不齐 | 按原图重建整表；group 列补 rowspan |
| 3 | **位段图/图内嵌内容被拆成表格行** | 偶见 | 表格中出现与列语义无关的行 | 并回解释单元格，用 `<br/>` 保持排版 |
| 4 | **O/0 字形混淆**（COP0→"COPO"） | 偶见 | 术语表/指令名核对；特定指令集语境可推断 | 按标准记法修改 |
| 5 | **HTML 转义把 `&` 放大成 `&&`**（位与写成逻辑与） | 偶见 | 全文搜 `&amp;&amp;` | 改回单个 `&amp;` |
| 6 | **行内公式字符丢失**（`16'h0000` 丢一个 0） | 偶见 | 公式逐条对照原图 | 直接修改 |
| 7 | **条件符号 `!` 丢失**（互补跳转指令的 `!Rs[31]`） | 偶见 | 指令语义核对（互补指令的条件必然成对） | 补 `!` |
| 8 | **助记符与操作数丢空格**（`addi r7` → `addir7`） | 常见 | 搜 `[a-z]{3,4}r\d` 这类粘连模式 | 补空格 |
| 9 | **跨页段落被切成两段**。不只片边界——片内每次翻页都可能切断，且数量远多于片边界 | 多数接缝 | 规则化检测：左页末字符非终止标点（。！？：；…）且右页首字符是正文（非标题/图/表/列表/公式）；`qc_scan.py` 已覆盖 | 合并：两侧都是 ASCII 字母时补空格，否则直接衔接；目录、图注后、指令清单要排除 |
| 10 | **表下脚注丢失** | 偶见 | 查看原图表格下方有无小字 | 表后补一段 |
| 11 | 单元格内换行是**字面 `\n`** | 所有长文本表 | 搜 `\n` | 撰写阶段转 `<br/>`（属于 compose 的工作，不要在校准阶段修改） |
| 12 | **无逐段置信度** | 全书 | 低分清单恒为空 | 校准只能依靠体检脚本 + 表格对图 + 接缝核对；流水线已在有接缝时强制停留校准 |
| 13 | **汇编寄存器 `$` 记法与行内公式 `$…$` 冲突**（`$k1`、`JR $31`） | 涉及汇编的书 | 段落内 `$` 个数为奇数或 ≥3 | 撰写阶段按上下文判断：寄存器 `$` 按普通文本转义，不要当公式转换 |
| 14 | **原书自带笔误不是 OCR 错误** | 若干 | 对图核对——图上如此印刷的保持原样 | 不修改；"宁漏勿错" |
| 15 | **空白页/透印鬼影被解析成幻觉内容**（假公式、乱码标记、同段落重复多遍、成串日期、与本书无关的跨领域常识、凭空出现的人名） | 集中于空白/透印页 | `qc_scan.py` 的复读与关键词检测器；另外留意"上一页几乎空白"的页 | 整段删除 |
| 16 | **L/1 字形混淆**（`lw`→`1w`、`li`→`1i`） | 涉及汇编的书 | 指令助记符逐条核对 | 改回字母 L |
| 17 | **坏字形 □（U+25A1）**（标题/正文丢字） | 偶见 | 全文搜 □ | 按上下文补字 |
| 18 | **章标题缺失或被拆成两个标题**（章首大字页解析不稳） | 约三成章 | `toc_check.py`；逐章检查标题是否存在、是否与目录一致 | 缺失的按目录补插；拆开的合并；层级统一 |
| 19 | **表格结构损坏**（空壳表/整列丢失/表头错位，宽度阈值挑不出） | 部分复杂表 | `table_tool.py check` 的格数不一致清单 + 逐张对图核对 | 整表换图：`table_tool.py crop --extra 页:序号`，表题保留为正文 |

**PaddleOCR-VL 的强项**（可少操心）：页数对账准确（无丢页）；复杂表头结构
（双级表头 + rowspan/colspan、数学符号逐格正确）；图注编号与正文段落完整性。

**通读方式**：先全局模式搜索，再按 50～100 页分批通读；表格必须逐张对图，
正文抽样看图即可。

### 规矩

- 只修改识别错误的地方。不要重写文案、不要调整风格、不要补充原文没有的内容。
- 图上确认解析无误的，保持原样。
- **认不出来的宁可不改**——改错比不改更糟。把情况写进 `calibrate/notes.md`。
- 所有改动记录在 `notes.md`：改了什么、依据是什么。后续复核者会看。

## 关卡二：撰写（compose）

### 交付物

```
<run>/build/
├── BRIEF.md          ← 撰写说明
├── book.json         ← 书目 + 阅读顺序（模板已就位）
└── OEBPS/
    ├── text/         ← ★ 章节正文写在这里
    ├── images/       ← 脚本搬好的图
    └── style/base.css
```

### 撰写脚本

小书可以用一条命令成稿：

```bash
python scripts/compose_mathml.py --run <run 目录> \
    --title "书名" --author "作者"
```

它完成机械部分：标题分级、段落/列表、`$$…$$` 与 `$…$` 转 MathML、公式编号
右对齐、转义、`book.json`。**需要 `pip install latex2mathml`。**
注意它会清空 `text/` 一次性重写——长书按章分批手写更稳（见「长文档」一节）。

按 `#` 分章、有前置页的书，使用 [`scripts/compose_book.py`](compose_book.py)：
它不猜测边界，读取 `build/compose-plan.json`（撰写者写好的行区间、标题、目录
层级），其余机械工作照做（表格、插图、代码清单、印刷目录、多级导航锚点）：

```bash
python scripts/compose_book.py --run .pdf2epub/runs/<id> --audit   # 先看审计，不写文件
python scripts/compose_book.py --run .pdf2epub/runs/<id>           # 写章节 + book.json
```

它是示例脚本而非流水线的一步——章节怎么切、标题叫什么，由撰写者决定并复核。
脚本执行完**必须检查**：

- 切出的章数是否正确（标题层级启发式按特定后端产物调整过；换后端先复核层级）
- 标题是否被截断或粘连
- 印刷目录的页码是否仍与原书对应

### 章节 XHTML 的硬要求

只有三条：良构 XML、根元素带 XHTML 命名空间、有 `<head><title>` 与 `<body>`。
`content.opf` / `nav.xhtml` / `META-INF/container.xml` **无需撰写者处理**，
打包时自动生成。

**公式必须是合法 MathML。** 仅仅"XML 良构"不够——`<msup>` 这类元素只允许
固定个数的子元素，超出后 XML 仍可解析，但 EPUBCheck 会判 RSC-005。
`scripts/compose_mathml.py` 的 `bad_structure()` 就是拦截这类问题的。

## 关卡三：格式（check）

脚本执行自检 + EPUBCheck，结果写入 `check/report.md`，精确到文件、行号、
原文片段。**这里只有报告，没有修复器**——修改是 LLM 的工作，脚本负责把问题
定位得足够准。

### 常见问题归属

| 码 | 含义 | 归谁处理 |
| --- | --- | --- |
| `OPF-014` | 用了 MathML 但 manifest 未声明 | **脚本**（`epubpack` 已自动探测） |
| `RSC-005` | XHTML 解析失败 **或** MathML 结构违规 | LLM（修改 `build/` 下的文件） |
| `RSC-006` | 引用了远程资源 | LLM（EPUB 不允许远程资源） |
| `RSC-007` | 引用的资源不存在 | LLM（可能真丢了图，需看上下文决定补图还是改写正文） |
| `OPF-085` | `identifier` 标了 `urn:uuid:` 但不是合法 UUID | **脚本**（已自动纠正） |
| `OPF-003` | manifest 与目录树不一致 | **脚本**（打包时按目录树重建） |

判断标准：**包内文件层面的问题（OPF/nav/container/zip）归脚本，正文层面的
问题（内容、引用、MathML）归 LLM。** 如果某个包内问题反复出现，那是脚本的
缺陷，应到 `src/pdf2epub/` 修复，而不是每次手工绕过。

### 确实无法修复的

`pdf2epub done --accept --note "原因"` 收尾。产物保留，同时留下明确告警，
**不会静默标记为成功**。不要为了让它"通过"而删除或注释掉内容。

## 已知教训

以下问题都在实际转换中出现过。前几条已在代码中修复，了解原因可以省去下次
排查的时间；其余是操作方式上的纪律。

### 1. 解析产物的 bbox 可能有多套坐标系

历史后端的版面层是 0-1 归一化、正文层是 0-1000 整数归一化、真像素需要页面
尺寸换算。只归一化一边时 IoU 无法匹配，**低分段会被整批贴错页码**——而且错得
静默无声，报告看着正常，只是页数不对。坐标基准的判定必须**整份文档统一做**，
不能逐页判断：某页恰好只有一小块内容时，逐页判断会误判坐标基准。

### 2. 版面层是逐行、正文层是整段

带分数的是逐行 OCR 结果，正文条目是整段。只比 IoU 的话，逐行框与整段框重叠率
很低，**正文和公式会整片配不上分数**，而那恰恰是最需要复核的部分。改为
"至少一半重叠"后，配上分数的段落大幅增加。一段命中多行时取**最低**分：
整段里只要有一处没把握，这段就值得看一眼。

### 3. `\binom{a}{b}^\top` 会产生非法 MathML

latex2mathml 会把上标挂到残缺的基上，产出 `<msup>` 中子元素超限的结构。
XML 良构、能解析、能打包，**只有跑真校验才会暴露**（已在示例脚本的
`sanitize()` 中兜住）。遇到"生成的 XML 看着没问题但 EPUBCheck 报 RSC-005"，
先怀疑**结构合法性**问题，而不是语法问题。

### 4. 提交信息写一行标题即可

没有读者；长描述不会带来任何价值。

### 5. 测试不应产生批量删除

pytest 默认只保留最近 3 次会话的临时目录，每次运行都会整棵删除更早的那一份
（一次数百个文件）。沙箱化的 IDE 会把这种批量删除当作破坏性操作拦截，agent
就无法持续自动运行。`tests/conftest.py` 已覆盖内置 `tmp_path`：每个测试一个
独享目录、永不自动删除；代价是临时目录需要手动清理。

### 6. 撰写阶段的四个坑

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| EPUBCheck `RSC-005`：`value of attribute "width" is invalid` | 解析产物给出 `<img width="79%">`，而 XHTML 的 `width` 只接受整数 | 百分比挪进 `style="width:79%"` |
| MathML 产物 `xmlParseEntityRef: no name` | 公式里的 HTML 实体被 latex2mathml 当成数学字符，产出一个**裸 `&`** | 转换前把实体还原成原始字符 |
| 产物 `error parsing attribute name` | `\text{…}` 里的 `<` 漏转义，产出 `<register_list>` 这类假标签 | 把"不在 MathML 标签表里的尖括号"转义掉 |
| 一批"MathML 结构不合法"，手工转换却正常 | 修复正则的 `/?` 会**回溯成空匹配**，合法的 `</mi>` 也被当作假标签转义掉——自制的"修复"反而制造问题 | 开标签与闭标签的否定前瞻拆成两条规则 |

另有一处只能靠上下文判断：`$` 既是数学定界符又是汇编寄存器前缀。只保护
**确实**是寄存器的写法（`$31`/`$k0`/`$k1`）；形如 `$ 7+3=10 $ns` 里的 `$ns`
绝不能保护，否则数学会被拆坏。

### 7. 切章规则与解析后端绑定，换后端就得显式提供

脚本按 markdown 层级猜章节，但不同后端的层级约定完全不同（章是 `#` 还是
`##`、节小节的编号形态、前置页怎么分——这些猜不出来）。结论："切章"由撰写者
提供表，而不是让脚本猜：`scripts/compose_book.py` 读取
`build/compose-plan.json`（行区间 + 标题 + 目录层级）。两个必查项：
**章首标题是否缺失或被拆成两行**；**印刷目录的页码是否仍对应原书**。

### 8. 大书解析与修复链的四条纪律

**（1）解析任务分批提交，不要一次性全发。** 连续提交大量分片时会出现限流
（HTTP 429）乃至被拒（HTTP 400），而流水线是"全部提交成功后才写
`parsing/jobs.json`"——先提交的任务编号只存在于日志里，无法接续，重跑还会
重复提交。按批走：`scripts/submit_jobs.py --batch 6 --pause 4`（逐个落盘
job_id、被拒退避重试）→ `scripts/fetch_jobs.py` 取回 →
`pdf2epub run --until prepare`（跳过提交、只做接缝校验）。

**（2）页边页码方框会被读进正文，形态比预想的多。** "跨页扫描再切开"的书，
页边页码方框紧贴正文行时会被整页模型顺着读进来：句中截断（`另58一个没有…`）、
句首（`444 表6-4显示`）、独立成段（`27`、`[27]`、`A-14`）、甚至被当成公式
（`$ \boxed{15} $`）或读进图注。整本书可清出数十处。**判定标准只有一条：
删掉之后句子通顺**；先用 `中文 + 1~3 位数字 + 中文` 的模式扫一遍
（`qc_scan.py` 已内置），再对可疑处看图。

**（3）source.md 只能由一个脚本生成。** 多个脚本各自从原始产物重写 source.md
时，后执行的那个会把先执行的改动静默抹掉（去重结果被覆盖是真实发生过的事故）。
修复链必须收敛到**单一入口**，依次执行：去重 → 删页码段 → 定点修复 → 公式
规范化 → 全局替换 → 写盘；同时产出 `page-lines.json`（原书页 → source.md
行号），撰写阶段切章依赖它。两条硬约束：
- 全局替换**行内进行**，不许改变换行数（行号映射会失效）；
- 每条替换要求**全文唯一命中**，不唯一就报错停下（宁可停下来核对，也不要改错位置）。

**（4）latex2mathml 与"定界符配对"的两个具体陷阱。** `\sum\limits` 转不动，
整条公式会退化为纯文本（`\limits` 直接删除即可）；`re.search(pattern, s, pos)`
的第三个参数是 **flags** 不是起始位置——写成 `re.search(p, s, pos)` 会静默
使用错误的 flags（或抛 `cannot use LOCALE flag`），应使用
`re.compile(p).search(s, pos)`。另外**摘除 `$…$` 前先数 `$` 的奇偶**：正文里
夹着 `L2$`、汇编寄存器 `$31` 时配对不可信，宁可整段不动。

### 9. 宽表和坏表的正确形态是图，不是 HTML

全量对图核对表格后的结论：**数值几乎不出错**，问题集中在两处——助记符/
寄存器名的字形混淆（0↔O、1↔I、点号丢失），和**公式类单元格被读坏**（箭头
反向、上下标成乱码、MathML 占位符）。后者修不如换：结构已坏的表（空壳表、
整列丢失、表头错位）整表替换为从 PDF 裁出的图，坐标使用解析器给出的表格
bbox（`scripts/table_tool.py crop`）。裁图判据只看宽度（见关卡一的表格流程），
不要把"行多"的表也换成图——纵向滚动能忍，不能搜索不能忍。

另一个教训：**先改了语义、后对图的，要肯改回来。** 某表题中的"ECS"看着像
"EC2"的笔误，改了；对图确认原书就印的 ECS，又改了回去。原书笔误不是 OCR
错误（见高频问题 #14），一切以图为准。
