# 干活指南（给驱动这个工具的 Agent / 人）

README 讲的是**工具本身**。这份讲的是**你在三个关卡上具体该怎么干**，
以及已经踩过的坑——那些坑不写下来，下一轮一定会重踩。

## 先把分工记住

| 谁 | 干什么 |
| --- | --- |
| MinerU | 解析 PDF：OCR、版面、阅读顺序、逐段置信度 |
| 脚本 | 搬运、渲染页面图、打包、校验、出报告 |
| **你** | **判断与转写**：对着页面图校准低分段；把内容写成 EPUB |

脚本停下来的三个地方，都是它在说"这里需要判断，我判断不了"。

---

## 循环

```bash
pdf2epub run                              # 跑到需要你的地方，退出码 3
pdf2epub show calibrate|compose|check     # 直接看工单，不用翻路径
#  …… 干活 ……
pdf2epub run                              # 继续；已完成的阶段不会重来
```

退出码：`0` 成功 / `1` 失败 / `2` 跑完了但有告警 / `3` **轮到你了**。

阶段重跑会自动把后面的阶段重置回 pending，所以不用担心旧状态残留。
反复跑同一个命令是安全的。

## 关卡一：校准（calibrate）

### 会给你什么

```
<run>/calibrate/
├── report.md       ← 工单：低分段清单 + 原文 + 上下文 + 对应页面图路径
├── segments.json   ← 同一份清单，机器可读
├── source.md       ← ★ 你直接编辑这个
├── pages/          ← 页面截图（page-0007.png = 第 7 页）
└── images/         ← MinerU 抽出的图
```

### 怎么干

1. **先看 `report.md`**，它按分数升序列出低分段。
2. **逐页打开 `pages/*.png`**，把图上内容和工作稿里的对应段落比。
3. 只改**确认是识别错误**的地方，改在 `source.md` 里。
4. 改完 `pdf2epub run`。确认不用改就 `pdf2epub done calibrate --note "…"`。

### 别一页页硬啃，先按模式找

实测一篇 18 页的 LaTeX 论文有 55 段低分内容，逐段核对很慢。真正有效的是
**先按已知的错误模式全局搜一遍，再对可疑处看图确认**。上一轮用到的模式：

| 想找什么 | 搜什么 |
| --- | --- |
| 公式右边被吞了符号 | `$= `（美元号后直接等号）；`= \operatorname{diag}` 前面没有变量 |
| `Λ` 被吞或被认成别的字 | `\\mathbf { \\Psi }`、`\\mathbf { \\omega }`、`对角矩阵 \$= ` |
| 下标被吞成纯文本 | 中文紧挨着一个孤立字母，如 `∪ M 的特征值集合`（应是 `M₋`） |
| 字符被当成排版符号 | `\\underline { { \\mathbb { E } } }`（应是"正"）、`\\textsf { F }`（应是"下"） |
| 中文引号被输出成 `” ` | `” `（右引号夹空格） |
| 被认成一串上标 | `<sup>作用于</sup> <sup>A</sup>` |
| 残余杂质 | 中文里多出的 `o`（应是句号）、` e e`、多余右括号 |
| 空基导致的怪结构 | `& ^`、`& _`（数组单元格里只有上标、没有底） |

**改之前必须看图。** 这些模式只负责"值得看一眼"，不负责"确认是错的"。
上一轮有一处 `m₁` 我按上下文推断应为 `m_i`（同页另两处都是 `m_i`，且指数必须
跟着下标走），这是少数靠推理定的，也记在了 `notes.md` 里。

### 规矩

- 只改识别错的地方。不要重写文案、不要调风格、不要补原文没有的内容。
- 图上确认机器没认错的，保持原样。
- **认不出来的宁可不改**——改错比不改更糟。把情况写进 `calibrate/notes.md`。
- 改动记一份 `notes.md`，说明改了什么、依据是什么。下一轮或用户会看。

## 关卡二：撰写（compose）

### 会给你什么

```
<run>/build/
├── BRIEF.md          ← 撰写说明
├── book.json         ← 书目 + 阅读顺序（模板已放好）
└── OEBPS/
    ├── text/         ← ★ 你写章节
    ├── images/       ← 脚本搬好的图
    └── style/base.css
```

### 用现成的脚本

```bash
python scripts/compose_mathml.py --run <run 目录> \
    --title "书名" --author "作者"
```

它把机械的部分做掉：标题分级、段落/列表、`$$…$$` 与 `$…$` 转 MathML、
公式编号右对齐、转义、`book.json`。**需要 `pip install latex2mathml`。**

它是示例脚本，不是流水线的一步——章节怎么切、标题叫什么，仍然由你定，
也应该由你复核。脚本跑完**务必检查**：

- 切出来的章数对不对（MinerU 把一级章和二级小节都输出成 `##`，
  靠"编号里有没有点"区分；`摘要`/`目录`/`参考文献` 这类没有编号，算一级章）
- 标题有没有被截断或粘连
- 目录章（印刷目录）的页码是否还对着原书

### 章节 XHTML 的硬要求

只有三条：良构 XML、根元素带 XHTML 命名空间、有 `<head><title>` 和 `<body>`。
`content.opf` / `nav.xhtml` / `META-INF/container.xml` **不用你管**，打包时生成。

**公式必须是合法 MathML。** 仅仅"XML 良构"不够——`<msup>` 这类元素只允许
固定个数的子元素，塞多了 XML 照样能解析，但 EPUBCheck 会判 RSC-005。
`scripts/compose_mathml.py` 里的 `bad_structure()` 就是拦这个的。

## 关卡三：格式（check）

脚本跑自检 + EPUBCheck，把结果写成 `check/report.md`，精确到文件、行号、原文片段。
**这里只有报告，没有修复器**——改是"你"的事，脚本负责把问题定位得足够准。

### 常见问题归谁

| 码 | 含义 | 谁该处理 |
| --- | --- | --- |
| `OPF-014` | 用了 MathML 但 manifest 没声明 | **脚本**（`epubpack` 已自动探测） |
| `RSC-005` | XHTML 解析失败 **或** MathML 结构违规 | 你（改 `build/` 下的文件） |
| `RSC-006` | 引用了远程资源 | 你（EPUB 不允许远程资源） |
| `RSC-007` | 引用的资源不存在 | 你（可能真丢了图，要看上下文决定补图还是改写正文） |
| `OPF-085` | `identifier` 标了 `urn:uuid:` 但不是合法 UUID | **脚本**（已自动纠正） |
| `OPF-003` | manifest 与目录树不一致 | **脚本**（打包时按目录树重建） |

判断标准：**包内文件层面的问题（OPF/nav/container/zip）是脚本的活，正文层面的
问题（内容、引用、MathML）是 LLM 的活。** 如果发现某个包内问题反复出现，
那是脚本的 bug，应该去 `src/pdf2epub/` 修，而不是每次手工绕过去。

### 实在改不动的

`pdf2epub done --accept --note "原因"` 收尾。产物保留，同时留下明确告警，
**不会静默当成功**。不要为了让它"通过"而把内容删掉或注释掉。

## 已经踩过的坑

跑第一份真实 PDF 时暴露出来的。前三个已经在代码里修好了，但知道原因能省下
下次的排查时间；后两个是使用方法上的教训。

### 1. MinerU 的 bbox 有**三套坐标系**（已修）

| 来源 | 坐标系 |
| --- | --- |
| `model.json`（vlm 模式，版面层） | 0-1 归一化 |
| `content_list.json`（正文层） | **0-1000 整数归一化** |
| 真像素 | 需要页面尺寸才能换算 |

原来的实现只把一边归一化，两套坐标比不出 IoU，**55 段低分段全被贴上第 1 页**。
页码错得静默无声——报告看着正常，只是页数不对。

实测同一份产物里，`content_list` 的 `[292,135,702,185]` ÷ 1000 正好等于
`model.json` 的 `[0.294,0.136,0.703,0.186]`。

判定必须**整份文档统一做**，不能一页一页判：某页恰好只放了一小块内容时，
按页判断会把这一页误判成 0-1 坐标，于是只有这一页配不上分数，更难发现。

### 2. 版面层是**逐行**、正文是**整段**（已修）

带分数的是 `ocr_text`——逐行的 OCR 结果；`content_list` 的条目是整段。
只比 IoU 的话，逐行框和整段框重叠率很低，**正文和公式会整片配不上分数**，
而那恰恰是最需要复核的部分。改成"至少一半重叠"后，配上分数的段落
从 185/290 涨到 246/290。

一段命中多行时取**最低**分：整段里只要有一处没把握，这段就值得看一眼。

### 3. `\binom{a}{b}^\top` 会产生**非法** MathML（已在示例脚本里兜住）

latex2mathml 会把上标挂到残缺的基上，产出 `<msup>` 里塞四个子元素的结构。
XML 良构、能解析、能打包，**只有跑真校验才会暴露**。

记在 `scripts/compose_mathml.py` 的 `sanitize()` 里。以后遇到"生成的 XML 看着没
问题但 EPUBCheck 报 RSC-005"，先怀疑这类**结构合法性**问题，而不是语法问题。

### 4. 提交信息别写长

用户明确说过："没人看"。一行标题就够。
